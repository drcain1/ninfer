NInfer Volta 232,000-token context qualification — 2026-11-05

Recommendation
The tested 232K configuration is usable for one long conversation interleaved
with smaller requests, with the existing 8.59 GiB host-cache budget. It did not
reproduce the old multi-minute warm-prefill stalls. Keep 200K as the default when
predictable latency matters more than the extra context; 232K is a reasonable
option when needed, accepting the cold-prefill and concurrency costs below.
Production was restored at 200000 tokens with its files unchanged. A real
reasoning_effort=high arithmetic request passed after restoration.

Interpretation
Cold prefill was computationally expensive and continued to make progress; the
initial roughly 12-minute wait is still real. Prefix caching avoided repeating
that full cost on subsequent turns. Near capacity, checkpoints sometimes stopped
advancing temporarily, requiring up to 679 tokens of replay. The exact repeat
still replayed that suffix and took about seven seconds. Cache retention therefore
worked, but it was not free of extra work or latency variation.
The host context pool approached its capacity. The overlapping 16K prefill raised
the long request's first-output delay to about 25 seconds. No CUDA allocation
failure, HTTP rejection, service crash, or multi-minute warm stall was observed.
System-wide swap activity includes unrelated processes; the server itself did not
swap. The spare 3.19 GiB is measured host headroom, not a general memory guarantee.

Limits
This is one replay, not a soak or a general concurrency/quality qualification.
Most warm turns appended 16 corpus words plus tool framing (roughly 68–69 prompt
tokens); the near-limit turn added 477 prompt tokens. Its median latency must not
be compared directly with the previous 150K–180K replay's larger appended chunks.
We did not test two independent 232K conversations, long high-effort reasoning
outputs at this boundary, arbitrary large tool outputs, or multimodal expansion.
Reserve output space: e.g. an 8192-token output budget leaves at most 223808 tokens
for the fully rendered input within a 232000 total context. Template and tool
framing count too. The nominal ceiling is 232000 tokens, not 232 * 1024.
Memory telemetry began 77.3 seconds into cold prefill because this kernel lacks
/proc/pressure/memory. A separate monitor then sampled the remaining cold phase
and all warm/pressure/concurrent phases. Startup/initial memory peaks are not
qualified by these measurements. The optional PSI metric was unavailable.
